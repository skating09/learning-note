一、调试器使用

劳德巴赫

Trace32使用

1. 查看函数

点击下图红色方框内的感叹号，出现Symbol.Browse对话框，在左侧方框内填入函数名字，然后回车，会显示该函数。


双击该函数，显示函数代码，浅绿色的是每一行代码对应的汇编代码，点击‘Mode’关闭汇编代码显示。

2. 断点

在代码左侧的行号处双击，可以再该行打断点，代码运行到该行会停止。再次双击取消断点。
点击‘Break’->‘List’可以查看所有的断点,

点击‘Break’->‘List’可以查看所有的断点，可以删除某些断点，也可以删除所有断点。

条件断点
右键点击变量，选择‘Breakpoint’，可以针当前变量设置一个断点。

3. 查看变量值

‘Var’->‘Show Watch’。
把当前的Var.Watch窗口最小化后，再点击‘Var’->‘Show Watch’，可以打开第二个Var.Watch窗口。


右键点击变量，可以把变量加入到Watch中。

4. 代码运行

Step：单步执行，每一次只执行一行代码。遇到调用函数会进入该函数单步执行。
Over：在当前函数内单步执行，不会进入调用的函数单步执行，
Go：继续执行直到遇到下一个断点。

‘View’->‘List Source’，显示当前系统停在的代码位置。

查看运行时间
查看从系统开始执行指令到当前时刻的运行时间。可用于测量系统上电后到某一阶段（例如初始化）的时间。
查看两个断点之间的执行时间，可用于测量函数的执行时间，Task执行一个Cycle所需的时间。

5. CPU Target Reset

点击‘In Target Reset’，可以使CPU复位，从而可以重新开始测试。


6. Store / Load 配置文件
可以使用Store Window功能把当前调试页面的所有信息保存到*.cmm文件中，重新启动调试后使用Load Window功能加载调试信息，这样就不需要每次调试都要重新打开函数代码，不需要重新加载变量到Watch上。

2. 编译

完整的编译过程如下，命令可以使用 && 连接，表示顺序执行。
make clean && make clean depend && make depend && make all

  1. make clean
    删除生成的目标文件

  2. make clean depend
    删除目标文件的依赖文件 （每一个源文件都对应生成一个依赖文件，主要描述源文件需要的头文件。）

  3. make depend
    生成目标文件的依赖文件

  4. make / make all / make -j
    三个 make 方式都可以。make与make all无太大区别。
    在多核系统上，make –j 会创建多个编译任务，加快编译的速度。

  5. make -j > a.log
    输出重定向，所有的编译信息都会输出的文件a.log中，而不会显示在cmd窗口上。

  6. make -j 2> a.log
    错误输出重定向，编译错误信息会输出的文件a.log中，而不会显示在cmd窗口上。以便在编译信息太
    多时方便查看编译错误。
    如果编译过程中出现错误，修改代码之后，重新编译，只需要执行 make –j 就可以了，不需要执行
    make clean && make clean depend && make depend，这样会浪费时间。

如果新增了源文件或者头文件，则需要重新执行整个编译过程：
make clean && make clean depend && make depend && make all

  1. tresos gui主界面
  2. 修改生成代码的路径
    大部分情况下，生成的代码只是部分替换掉开发工程中的文件，而默认的代码生成路径与本地代码一致，导致开发工程中的文件混乱。可以选择其他路径存放EB生成的代码，方便对比及合并文件。
    在工程图标上点击右键，选择Properties，然后修改Configuration Project->Code Generator
    ->Generation Path，设置相应路径，路径可以不存在，EB生成代码时会自动创建。
  3. 生成文件对比及合并
    EB生成的文件只需要关注include及src目录下的文件。
    文件合并过程中，只合并修改的模块以及管理的模块，其他模块即使文件不一样，也不要修改。
  4. Window view
    常用的窗口
    Description：显示配置项的描述信息
    Informatica：配置项的config信息
    Errors：EB工程生成代码过程中的错误提示信息（有些错误智能在生成代码过程中发现）
    Problems View：配置过程中的错误提示信息（有些配置项设置错误，窗口也能直接显示错误）
    Sidebar：配置辅助工具，主要用于CAN及NVM模块。
  5. Problems View
    配置过程中检测到的错误，配置项会出现红色的“x”，可以根据提示的错误信息找到解决方法。
    这个gui的反应速度比较慢，所以有时候配置正确，红色的“x”仍然会显示很长时间。
  6. Search
    使用EB配置的过程中经常会用到搜索功能。
  7. Generate Code
    点击“Generate Code”，如果配置项无错误，则会在对应路径生成代码。
  8. xdm文件
    EB工程各个模块的配置信息都放在对应的xdm文件中。
    可以通过对比xdm文件查看模块配置项的修改信息。
    也可以直接手动修改xdm文件。
